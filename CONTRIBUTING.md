# Contributing

Read `AGENTS.md` and the specifications first. Keep changes within the approved roadmap phase. Propose model changes with a decision record and observable acceptance criteria; do not present untested biological hypotheses as established behavior.

Use Node.js 24 and `npm ci`. Use `npm run dev` for development, `npm test` for a single test run, `npm run test:watch` for watch mode, and `npm run check` before opening a pull request. Commit `package-lock.json` when dependencies change. Dependencies are development/build inputs; application runtime must remain local.

For the optional real-browser smoke check, run `npx playwright install chromium firefox` followed by `npm run test:browser`. On Linux CI images, browser installation may require `npx playwright install --with-deps chromium firefox`. The script starts/stops a production preview on 4173 and a dev-only reproducibility harness on 4174. Run `npm run build` first. It checks keyboard entry, save/load, real file download/upload, native Canvas output, narrow-screen reflow, and absence of external runtime requests. It complements the DOM tests; it does not certify accessibility.

For the current in-progress life work, continue from `codex/integrated-life-baseline` (PR #4), not the older `main`; see `RESUME.md`. Create a dedicated local branch and show the tested result before publishing, according to the owner's current local-work setting. Describe the problem, resulting behavior, relevant specifications, validation evidence, and limitations in a pull request. Test behavioral boundaries, rather than mirroring implementation. Check keyboard access, zoom/reflow, narrow screens, storage failures, and exported file portability when relevant. Do not merge automatically.

The Phase 1 suite preserves all 36 foundation tests. New model expectations come from the independent Python per-site oracle in `scripts/reference-fixtures.py`; `--check` verifies committed fixtures without rewriting them. Do not regenerate fixtures using production functions. `npm run benchmark` measures pure-engine Node timing and process ArrayBuffers; browser reproducibility checks also log engine/batch timings. Record measurements and limitations when changing numerical semantics or limits. Definition exports restart; do not introduce checkpoint claims without a format decision.
